Privacy Policy

QQR is a Chrome extension for scanning and creating QR codes, with additional tools for common linear barcodes. It can also keep the one-time codes for your two-factor authentication (2FA) accounts in an encrypted vault on your device. This policy explains how QQR handles information.

Effective November 26, 2026

Summary

QQR processes information locally on your device. It does not send your data to the developer, third parties, or external servers, and it does not use analytics or tracking services.

Information QQR processes

QQR may process the following information only when you request the related feature:

  • The visible screenshot of the active tab when you start a QR or barcode scan.
  • The page region you select and the QR or barcode value decoded from it.
  • A PNG, JPEG, or WebP image you select, paste, or drop for QR or barcode decoding.
  • Webcam video, only after you start camera scanning in the workspace and allow camera access. Frames are decoded in memory and discarded immediately; video is never recorded, stored, or uploaded.
  • A list of values or a CSV file you provide for bulk QR creation.
  • Text or URLs you enter to generate a QR code.
  • Wi-Fi, contact, email, SMS, phone, calendar, location, WhatsApp, or VietQR bank transfer details you enter into a QR template. Bank details are never looked up online.
  • An optional PNG, JPEG, or WebP logo you select for a generated QR code.
  • Text or numbers you enter to generate a barcode.
  • For the 2FA tab: a password you choose, and the 2FA account details you add (service name, account name, setup key, and code settings), from a QR scan, a setup key you type, or a Google Authenticator "Transfer accounts" QR code. They are kept only in the encrypted vault described under "2FA codes" below.
  • The last popup tab you used, and your 2FA auto-lock choice, so QQR can reopen where you left off.
  • Your selected interface theme and language, and QR style settings.
  • Optional local history of ordinary text and web links, only if you turn it on. Wi-Fi, contact, payment, authentication, and 2FA setup code content is never saved.
  • Saved QR styles, only when you save one. A style can include a small copy of your logo only if you choose to include it.
  • A local count of successful scans and exports, used only to show a one-time invitation to rate QQR.

Website screenshots are held temporarily in extension memory while a scan is in progress and are discarded after the selected area is processed or the tab is closed. Selected images, QR or barcode values, generated PNG or SVG images, and logos are processed locally and are not uploaded. When a context-menu action is used, or when a page-area scan finds a 2FA setup code, QQR keeps the selected value or scan result in Chrome's in-memory extension session storage only long enough to open the toolbar popup, then removes it. A 2FA setup link handed over this way stays only in that memory-only storage until it is read or Chrome closes.

A decoded value or generated image is written to the system clipboard only when you request it. Your theme and language are saved in browser-local extension storage so they persist between sessions. You can remove these preferences by clearing extension data or uninstalling QQR.

2FA codes

The 2FA tab is optional. Nothing is stored for it until you choose a password and turn it on.

  • Encrypted vault. Your accounts are stored in browser-local extension storage as an encrypted vault. QQR protects them with a random data key. That key is itself encrypted with a key derived from your password (PBKDF2-SHA256 with 600,000 iterations), and the accounts are encrypted with AES-256-GCM. Setup keys are never written to disk in plain text.
  • Password. The password is required and is never stored or sent anywhere. QQR cannot recover it. If you forget it, the only way forward is to erase the vault and start over, or to import a backup file whose password you remember.
  • Optional Touch ID or Windows Hello unlock. Where your browser supports it, you can choose to unlock the 2FA tab with your device's fingerprint, face, or screen lock. The browser and operating system run that check and keep the passkey they create for it; QQR never receives fingerprint, face, or other biometric data. After a successful check, the browser gives QQR a secret tied to that passkey, which QQR uses only to decrypt a second encrypted copy of the vault's data key kept inside the vault. Your password still opens the vault. Turning the option off removes that copy, and you can then delete the passkey in your browser's password manager.
  • Unlocked key in memory only. After you unlock the vault, the data key is held only in Chrome's in-memory extension session storage so your codes can be shown without asking again. It is removed when you choose "Lock now". After the auto-lock time you selected (15 minutes, 1 hour, 1 day, 7 days, or when Chrome closes; 7 days is the default) it stops working and is discarded the next time QQR is used, or when Chrome closes. It is never written to disk.
  • Nothing synced or transmitted. The vault is not synced between devices and is never sent to the developer, a third party, or any server. QQR makes no network request for 2FA codes, and one-time codes are calculated on your device.
  • Backups. You can export your accounts to an encrypted .qqr2fa file, protected with your current 2FA password or with a separate password chosen for that file, and import such a file later. The file is saved only where you choose; QQR does not upload it.
  • Scans never expose 2FA setup codes. When a scan finds a 2FA setup code, QQR does not copy it to the clipboard automatically, does not offer to copy it from the scan result, does not save it to history, and does not show it inside the web page being scanned. A code in the 2FA tab is copied only when you click it.
  • Removal. You can delete an account, erase every 2FA account from the tab, or clear all extension data or uninstall QQR to remove the vault.

Pages QQR opens

QQR opens a welcome page bundled inside the extension when it is installed. When QQR is removed, Chrome opens a public help page on this site. QQR attaches no identifiers, settings, or usage information to that address. The Chrome Web Store review page opens only if you click the rating button.

Data sharing and sale

QQR does not sell, rent, share, or transfer user data to third parties. It does not use user data for advertising, profiling, creditworthiness, lending, or purposes unrelated to its QR and barcode scanning and generation features or its on-device 2FA code feature.

Chrome permissions

QQR uses Chrome permissions only to provide its user-facing features:

  • activeTab temporarily accesses the visible tab after you start a scan.
  • scripting displays the QR or barcode area-selection overlay after a scan is started.
  • offscreen provides local canvas image processing and clipboard operations unavailable in a Manifest V3 service worker.
  • clipboardWrite copies decoded QR/barcode text, generated images, or a 2FA code when requested.
  • storage saves browser-local interface preferences, the encrypted 2FA vault, and a memory-only session key while the vault is unlocked.
  • contextMenus adds right-click actions to scan a visual or create a QR code from the current page, a link, or selected text.
  • sidePanel lets you open QQR's interface in the browser side panel. It does not grant access to page content.

QQR does not request permanent access to all websites and does not use remote code. Its QR and barcode processing libraries, including the WebAssembly decoder, are included in the extension package and are never fetched remotely.

Limited Use

QQR's use of information received from Chrome APIs complies with the Chrome Web Store User Data Policy, including the Limited Use requirements. Information is used only to provide or improve QQR's single-purpose code scanning and generation features, led by QR with additional barcode utilities and 2FA setup codes kept on your device, and is not transferred except where required by law or necessary for security.
